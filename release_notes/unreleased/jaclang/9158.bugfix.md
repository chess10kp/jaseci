- **Fix: native `sorted()`/`.sort()` key comparisons now use the canonical comparison path**: The native list-sort comparator used a private `icmp`/`strcmp` chain that mishandled most key types: `str` keys crashed LLVM verification (`E5020`), `bool` keys sorted in reverse (`True` before `False`), and tuple/list keys compared raw memory instead of their contents. `emit_sort` now delegates to the shared comparison emitter (`NaIRGenPass._emit_comparison`), so `str` keys compare length-aware and NUL-safe, `bool` keys order `False < True`, tuple and list keys compare element-wise, and bytes/set keys order correctly. Sorting an unorderable key (e.g. objects) reports `E5092` at compile time instead of sorting by pointer address. `bool`-vs-`bool` ordering operators (`<`, `>`, `<=`, `>=`) get the same `False < True` correction. Known limitation: no-key sorts of lists holding nested aggregates (e.g. `list[list[int]]`) are unchanged and remain unsupported; use an explicit `key=` (for example `key=lambda (x: list[int]) -> int { x[0]; }`).
