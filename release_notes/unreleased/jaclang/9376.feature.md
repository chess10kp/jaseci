- **Perf: escape-proven function-local list headers move from the heap into
  the frame**: A native list allocates two heap objects — the refcount/type
  header plus the data buffer. When escape analysis (`RcFactsPass`, new
  `na_list_stack_ok` stamp) proves a list display bound to a local never
  outlives its frame — no return, no alias into another local, global, field
  or closure, no user-call argument, re-bound only from other displays — the
  backend now constructs the header as a frame `alloca` (refcount slot set to
  the static sentinel) and keeps only the data buffer on the heap. Scope exit,
  loop-iteration exit, overwrite, and last-use releases route through a new
  data-only release helper that frees the buffer and releases elements but
  never the frame-resident header. Any channel the analysis cannot prove keeps
  today's heap header, so behavior is unchanged. Effect on tight append loops
  measured neutral under `clang -O2` (identical cycles/instructions per
  iteration against the `#9362` baseline, see
  `docs/architecture/native-list-append-performance.md`); the win is one fewer
  heap allocation and free per qualifying list construction — less allocator
  traffic and GC pressure for short-lived-list-heavy code.
