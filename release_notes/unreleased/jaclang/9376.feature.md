- **Perf: function-local list headers move from the heap into the frame**: A
  native list allocates two heap objects — the refcount/type header plus the
  data buffer — so every `append` dirtied both, and counter profiling of the
  100M-iteration churn loop attributed ~3.0 cycles/iter of store-buffer stalls
  to the header traffic. When escape analysis (`RcFactsPass`, new
  `na_list_stack_ok` stamp) proves a list display bound to a local never
  outlives its frame — no return, no alias into another local, global, field
  or closure, no user-call argument, re-bound only from other displays — the
  backend now constructs the header as a frame `alloca` (refcount slot set to
  the static sentinel) and keeps only the data buffer on the heap. Scope exit,
  loop-iteration exit, overwrite, and last-use releases route through a new
  data-only release helper that frees the buffer and releases elements but
  never the frame-resident header. Any channel the analysis cannot prove
  keeps today's heap header, so behavior is unchanged; the churn loop's
  remaining store-buffer stall signature drops to approximately zero.
