- **Feature: Sessions no longer start the database machinery until first use**: Constructing a `Session` (or asking `data_location()`/`repr()`, or committing/closing a never-used session) no longer builds the embedded-Postgres lease, store objects, or spawns the engine -- the store boots lazily, exactly once, on the first access that needs database truth or has work to persist. `data_location` answers from lease computation alone, so status probes stay spawn-free.
